# 028 — Rename Lyrx to Subbed

Status: approved

## Goal

"Lyrx" is already the name of a karaoke product and its domain is taken. The app becomes **Subbed** (domain `subbed.ca`), everywhere a learner, a developer, or the server sees the name. Nothing else about the app changes.

## In scope

- **Brand mark.** The wordmark `lyrx 歌詞` becomes `subbed 字幕` (*jimaku*, "subtitles"): lowercase `subbed` in the logo, "Subbed" in sentences. The search loading line `lyrx@歌詞 ~ translate` becomes `subbed@字幕 ~ translate`.
- **Icons and preview.** The favicon and Apple touch icon change from `歌` to `字`, the first kanji of the mark. The link preview image (`og-image.png`) is re-rendered with `subbed 字幕` and is otherwise unchanged.
- **Page text.** The tab title, `og:title`, "How Subbed works", "Songs already in Subbed", the "Could not reach the Subbed server" message, and the source code link (`github.com/itsvictorvelma/subbed`).
- **Code.** The Python package `backend/src/lyrx/` becomes `backend/src/subbed/`, with every import, the logger name, `pyproject.toml`, `uv.lock`, the run command (`python -m subbed`), and the frontend package name (`subbed-frontend`).
- **Settings.** Every `LYRX_*` variable becomes `SUBBED_*` (`SUBBED_HOST`, `SUBBED_ALLOWED_HOSTS`, `SUBBED_DATABASE_PATH`, `SUBBED_SECURE_COOKIES`, `SUBBED_TRUSTED_PROXY`, `SUBBED_PAGE_DIR`, `SUBBED_DOMAIN`), in `config.py`, `.env.example`, `Dockerfile`, `compose.yaml`, `Caddyfile`, and `scripts/deploy.sh`.
- **Stored names.** The `lyrx_session` cookie becomes `subbed_session`. The browser keys `lyrx-volume`, `lyrx-hidden-columns`, and `lyrx-theme` become `subbed-*`, and the Back marker in history state becomes `subbed`. The default database becomes `data/subbed.db`. The Docker service, volume, and system user become `subbed`. The LRCLIB user agent becomes `Subbed/0.1.0`.
- **Docs.** README, AGENTS.md, the `reviewer` agent, every file's opening comment, and `specs/README.md` (a row for 028). `docs/demo/lyrx-demo.mp4` is renamed to `subbed-demo.mp4`.
- **The user's local data.** `data/lyrx.db` is renamed to `data/subbed.db` (gitignored, not committed), so local songs and accounts stay.

## Out of scope

- **Old specs (001–027).** They stay as written: they record what was decided, like the `archive/cursor-v1` tag.
- **Migrating old browser settings or cookies.** Nothing is deployed, so the only effect is that local volume, hidden columns, and theme reset once, and the user logs in again.
- **Re-recording the README screenshots and demo video.** They still show the old mark, and recapturing them needs the running app. A follow-up for the user, listed in the PR.
- **Renaming the GitHub repo and the local folder.** The user does this after merge, from steps given in the PR.
- No changes to look, behaviour, or features.

## Rules

- No `lyrx` (any case) remains in tracked files outside the numbered spec folders (`specs/NNN-*/`, this one included, since it has to name the old app).
- Lock files are regenerated by their tools (`uv lock`, `npm install --package-lock-only`), not edited by hand.
- The new icons and preview image use only the existing colour tokens and fonts (spec 013). They are rendered the way spec 025 made them: HTML rendered once in headless Chrome, with the HTML not kept.

## Security

- **Settings with the old names are ignored, and that fails safe.** A server still set to `LYRX_ALLOWED_HOSTS` falls back to `127.0.0.1` and `localhost`, so it refuses outside requests and doesn't open up. Secure cookies come from the `Dockerfile`, which is renamed in the same change.
- **No secrets are involved.** The `.env` holds only the API keys, which keep their names.
- **Untrusted input, outside calls, and logging don't change,** apart from the user agent text and the logger name.

## Acceptance checks

- AC-1: A test finds no `lyrx` (any case) in tracked file names or text outside the numbered spec folders.
- AC-2: The header shows `subbed 字幕`, with `字幕` marked `lang="ja"`.
- AC-3: The search loading line shows `subbed@字幕`.
- AC-4: The tab title and `og:title` say Subbed.
- AC-5: Settings are read from `SUBBED_*` variables, and the default database is `data/subbed.db`.
- AC-6: Signing in sets the `subbed_session` cookie.
- AC-7: Volume, hidden columns, and theme are stored under `subbed-*` keys.
- AC-8: `python -m subbed` starts the server (the existing `test_main.py` covers this under the new name).
- AC-9: `scripts/check.sh` passes.

## Plan

- **Moves.** `git mv backend/src/lyrx backend/src/subbed` and `docs/demo/lyrx-demo.mp4` → `subbed-demo.mp4`, so history follows the files.
- **Text.** One scripted pass over every tracked text file outside the numbered spec folders: `LYRX` → `SUBBED`, `Lyrx` → `Subbed`, `lyrx` → `subbed`. Then `歌詞` → `字幕` only where it is the brand (header, search loading line and its test, README title), not in invented lyric lines. Read the prose diff for grammar and fix the `#` comments that were aligned in code blocks.
- **Locks.** `uv lock --offline` and `npm install --package-lock-only --offline`.
- **Images.** `favicon.svg` glyph `歌` → `字`. `apple-touch-icon.png` and `og-image.png` re-rendered from throwaway HTML in headless Chrome, with the colour tokens and Hiragino.
- **Tests.** A guard in `backend/tests/test_removed_code.py` (AC-1), a wordmark test in `HomePage.test.tsx` (AC-2), and the stored theme key pinned in `ThemeButton.test.tsx` (AC-7). The other ACs are covered by existing tests that now assert the new literal names.
- **Local only.** `data/lyrx.db` → `data/subbed.db`. `.env` needs nothing: it holds only the API keys.
